## 1. What should change and why

The request asks for two related but distinct visual updates to the website build:

1. Replace the current color scheme with a **Dark Blue and Orange** palette, applied consistently across the site's build output.
2. Make the page/site title (e.g., the `<h1>` or header element carrying the site or page name) **more visually dominant** — larger, bolder, and higher in visual hierarchy than it currently is.

The problem this solves is purely cosmetic/branding: the current site is presumably using a color scheme and title styling that the owner finds unremarkable or not aligned with the desired visual identity. There is no functional or content change implied.

**Ambiguity and chosen interpretation:**
- "Dark Blue and Orange" is not given as exact hex values. Interpretation: a dark navy/blue (e.g., roughly `#0A1F44`–`#1B2A4A` range) as the dominant background/base color, with orange (e.g., roughly `#E67E22`–`#FF7A00` range) used as the accent/highlight color (links, buttons, headings, borders). Exact shades are left to implementation but should read clearly as "dark blue" and "orange," not muted or pastel variants. This should be confirmed with the reviewer (see Open Questions).
- "Page/site title" is interpreted as the main heading that displays the site name and/or current page title (whichever the current template renders as the primary heading element). If the site has both a site-wide title (e.g., in a header/nav) and per-page titles, both should receive the same hierarchy treatment unless that proves visually redundant, in which case the site-wide title takes priority.
- "More visually dominant" is interpreted as: larger font size relative to body text, heavier font weight, and clear visual separation (spacing/color contrast) from surrounding content — not a full redesign of layout or typography system.

## 2. Scope

- Update the site's color scheme (background colors, text colors, link colors, borders, buttons/UI accents, and any theme variables) to use a dark blue base with orange as the accent color.
- Apply the new color scheme consistently across all pages generated by the site build, not just the homepage.
- Increase the visual prominence of the site/page title element:
  - Larger font size than current.
  - Bolder font weight.
  - Clear hierarchy distinction from subheadings/body text (spacing, possibly color using the new accent).
- Changes are limited to CSS/styling and, if necessary, minor template markup changes needed to support the new styling (e.g., adding a class to the title element if one doesn't already exist).
- Ensure basic readability/contrast is maintained with the new palette (text remains legible against backgrounds).

## 3. Out of scope

- No changes to site content, structure, navigation, or information architecture.
- No changes to page layout beyond what's needed to make the title more prominent (e.g., no redesign of grid/columns, no new sections).
- No introduction of a full design system, theming engine, or dark/light mode toggle — this is a single static color scheme change.
- No changes to fonts/typefaces unless strictly necessary to achieve "bolder" (using existing font family's bold weight is preferred over introducing new font files).
- No changes to images, logos, or icons (e.g., no recoloring of a logo asset) unless explicitly requested later.
- No accessibility audit beyond basic contrast sanity-checking — a full WCAG compliance pass is not part of this request.
- No changes to the build tooling/pipeline itself (e.g., no migration to a new static site generator or CSS framework), unless the current build has no styling mechanism at all, in which case the minimal necessary mechanism will be noted as an open question, not assumed.

## 4. Edge cases and error behavior

- **Invalid/missing color values:** If the build's existing stylesheet uses variables/tokens for color, ensure all relevant tokens are updated so no element is left in a stale/mismatched color (e.g., an orange accent on an old light background). If some colors are hardcoded inline rather than in a central stylesheet, those instances should be found and updated too, or flagged if too numerous to fully cover.
- **Contrast/readability failures:** If applying dark blue background with orange text (or similar combination) results in poor readability in some component (e.g., form fields, code blocks), that specific component should fall back to a readable variant (e.g., lighter text on dark blue, or dark text on orange) rather than strictly forcing the two-color scheme everywhere.
- **No single "title" element:** If the codebase has multiple candidate elements for "site/page title" (e.g., a logo text, a page `<title>` tag, an `<h1>`), only the visible on-page heading text is in scope; the HTML `<title>` tag (browser tab text) is not a styling target since it can't be visually styled.
- **Build/theme system unavailable or minimal:** If the site build has no centralized CSS (e.g., all styles inline per page), this will be flagged as an open question rather than silently duplicating style changes across many files.

## 5. Acceptance criteria

- [ ] Site-wide background and/or primary surface colors use a dark blue as the base color.
- [ ] Orange is used consistently as the accent color (e.g., for links, buttons, highlights, or the title) across all pages in the built site.
- [ ] The site/page title is visually larger and bolder than it was previously, and clearly stands out from body text and subheadings.
- [ ] The new color scheme is applied across all pages produced by the build, not just a single page.
- [ ] Text remains legible (reasonable contrast) against the new background colors on all pages.
- [ ] No content, navigation, or page structure changes were introduced beyond what's needed for the styling update.
